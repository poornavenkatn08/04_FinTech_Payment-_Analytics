# FinTech Payments Analytics — Fraud & Anomaly Monitoring

Transaction-monitoring analytics on 500K+ payments across 5 channels, using SQL
aggregations and a **Tableau monitoring dashboard** that surfaces anomalies and
reduces false-positive fraud alerts.

## What this demonstrates
- **Large-volume SQL** — aggregations and window functions over 500K+ transactions.
- **Anomaly detection** — statistical pattern recognition to flag suspicious behavior.
- **Operational BI** — a monitoring dashboard with drill-down from summary to individual transaction.

## Approach
1. **Aggregate** — analyzed 500K+ transactions across 5 channels with SQL window functions.
2. **Detect** — identified fraud indicators via statistical analysis, tuning to cut false positives.
3. **Monitor** — built a Tableau dashboard with automated refresh and calculated-field alerts.
4. **Drill down** — enabled investigation from channel-level summary to individual records.

## Key findings
- 500K+ transactions analyzed across 5 channels.
- **40%** reduction in false-positive fraud alerts through pattern recognition.
- Real-time anomaly monitoring enabled for stakeholders.


## Business questions this answers
- **Are our fraud alerts trustworthy, or are we drowning analysts in false alarms?** → false positives were reducible by 40% through better pattern recognition.
- **Can we spot anomalous payment behavior fast enough to act?** → yes, via a refreshing monitoring dashboard with drill-down to the individual transaction.
- **Which channels carry the most risk?** → channel-level monitoring isolates where anomalies concentrate.

## Recommendations
1. **Retune the alerting thresholds using the identified patterns** to cut false positives ~40% — this directly reduces analyst review load and alert fatigue, which is where fraud teams lose the most time.
2. **Adopt the monitoring dashboard as the daily operational view** so anomalies are caught in near-real-time rather than in retrospective reporting.
3. **Prioritize investigation by channel-level risk** rather than treating all transactions equally — focus scarce review capacity where anomalies cluster.
